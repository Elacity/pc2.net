# ENM v0.4 — Upgrade guide ("Welcome Home")

v0.4 is a **frontend-only** rebuild on top of the v0.3 backend. Every
v0.3 endpoint, healing rule, and database table is unchanged — only
the UI is different. Operators who liked the v0.3 5-tab dashboard get
it back via *Settings → For the technically curious → Show technical
details*.

This guide covers two things:

1. **Why the change** — what v0.3 felt like for first-time operators
   and what v0.4 fixes
2. **Path translation** — every "ENM → X" path from the v0.3 docs and
   where to find it in v0.4

---

## Why v0.4 exists

The v0.3 dashboard was a five-tab admin console (Dashboard / Logs /
Settings / Audit / EVM) with cards full of technical state badges
("HEALTHY", "SYNCING", "NOT CONFIGURED") and 4-stat grids next to each
chain.

Two operator categories found this hard:

- **First-time installers** had to learn what BPoS, keystore, RPC,
  sync height, and healing rule IDs (F1-F19) meant before they could
  feel confident. Some abandoned setup mid-wizard.
- **Casual maintainers** opening ENM weeks later wanted a one-glance
  *"is my node OK?"* answer, not a wall of stats.

v0.4 splits the audience:

- **Avg-joe path** — first-time installers see a wallet-style
  single-screen home. Welcome screen → 4-card setup conversation →
  hero card showing one big friendly status. Most operators never
  need anything else.
- **Power-user path** — the v0.3 dashboard is preserved verbatim
  inside the settings drawer. One tap (gear icon → *Show technical
  details*) and the full dashboard is back.

The design rule going forward: **friendly carrot in the headline,
technical noun in the role badge or subtitle**. So *Earn rewards*
appears as the carrot, but the subtitle says *Run a BPoS supernode*
— operators learn the real name they'll need in Essentials, on
explorers, and in support docs.

## v0.3 → v0.4 path translation

Every operator-facing path from the v0.3 docs, mapped to its v0.4
equivalent.

| What you used to do (v0.3) | v0.4 path |
|---|---|
| Click ENM launcher → see 3-step wizard | Click ENM launcher → see welcome screen → tap *Let's go →* → 4-card setup conversation |
| "Welcome → preflight checks" wizard step | Card A of the conversation — *What do you want to do?* (preflights run silently in the background) |
| "Install & Configure" wizard step | Card B (*Setting your ElastOS up*) + Card C (*Save your secret password*) — split for clarity |
| "Confirm & Start" wizard step | Card D (*🎉 You're all set!*) — clicking *Take me home* finalizes |
| ENM → Dashboard tab → Mainchain card | Home view (hero card). Technical detail is at Settings → *For the technically curious* → *Show technical details* → Status sub-tab |
| Mainchain card state badge ("HEALTHY", "SYNCING") | Hero card headline ("Your ElastOS is happy and earning"). The technical state badge is on the Status sub-tab in technical view |
| Mainchain card stats (Version / Height / Peers / Uptime) | Hero card *role badge* + the stat strip (💰 votes · ⏱️ uptime · 👥 friends). Full v0.3 stat grid is in Settings → Show technical details → Status |
| Mainchain card Start / Stop / Restart buttons | Hero card primary action (*Wake my ElastOS up* / *Pause my ElastOS*). The full Start/Stop/Restart trio is in Settings → Show technical details → Status |
| ENM → Logs tab | Settings → *For the technically curious* → *Show technical details* → **Logs** sub-tab |
| ENM → Settings tab → Network / Mainchain Advanced / General | Settings → *For the technically curious* → *Show technical details* → **Settings** sub-tab. (The friendly drawer above only surfaces the most common toggles — auto-restart, notifications, theme.) |
| ENM → Audit tab | Settings → *For the technically curious* → *Show technical details* → **Audit** sub-tab |
| ENM → EVM tab (v0.5 placeholder) | Settings → *For the technically curious* → *Show technical details* → **EVM** sub-tab. Same v0.5 placeholder, just nested |
| Producer identity card on Dashboard | Producer identity card on the home view (scroll below the hero). Same component; same content |
| Theme toggle in title bar | Settings drawer → **Appearance** → *Switch to dark mode* / *Switch to light mode* |
| Wallet badge in title bar | Removed in v0.4 (PC2's launcher / system tray already shows the operator's wallet — no need to duplicate) |
| Reconfigure (chain card "Configure" button when unconfigured) | Settings drawer → *For the technically curious* → **Reinstall my node**. (Or, when the home hero is in unconfigured state, tap *Set up my node* on the hero itself.) |

## Vocabulary rule reference

The eli5/technical split applied throughout v0.4. **Surface** these
real names — operators encounter them in Essentials, on explorers, and
in support docs:

- **BPoS supernode** (the earning role)
- **Council node** / **Council member (CR)** — distinct from BPoS
- **Full node** (the follower role)
- Sidechain names: **ESC**, **EID**, **ECO** (when v0.5 sidechain
  support lands)
- **RPC password**, **RPC user**, **WhiteIPList**, **log level**
  (settings drawer's technical sub-tab)
- **ELA**, **mainchain**

**Hide** these behind plain-English equivalents in the friendly view
(the technical view still uses them):

- *keystore.dat* (the file) → "secret password"
- *sync height* → "catching up" / "fully synced"
- *peer count* → "friends connected"
- *F1-F19 healing rule IDs* → "auto-restart on crash" / "let your
  node fix itself"
- port numbers, tps, block height — implementation detail

The same rule should govern any new copy added to v0.4 or v0.5
components.

## node.sh command parity (Wave 6)

Wave 6 closed three high-impact gaps from `node.sh` that previous
operators had to run by hand:

| node.sh function | ENM v0.4 endpoint | Where to find it in the UI |
|---|---|---|
| `ela_update` (line 1173) | `POST /api/enm/chains/:id/update` | Settings drawer → *Show technical details* → Status sub-tab → Maintenance → **Update binary** |
| `compress_log` (line 449) | `POST /api/enm/chains/:id/compact-logs` (already existed) | Same path → Maintenance → **Compact logs** |
| `ela_activate_bpos` (line 1590) | `POST /api/enm/chains/:id/bpos/activate` | Same path → Maintenance → **Reactivate BPoS supernode**. ALSO surfaces directly on the home hero card when `producer.state === 'Inactive'` |

These all run server-side using the keystore + binaries ENM already
manages. The keystore password is decrypted from
`cfg.dpos.keystorePasswordEncrypted` for each ela-cli invocation,
then the plaintext goes out of scope (no caching, no audit-log
exposure — same hygiene as the chain-start path).

### Theme follows ElastOS automatically

ENM now subscribes to PC2's `themeChanged` broadcast (puter-js
delivers it via `window.message` with shape `{msg:'broadcast',
name:'themeChanged', data:{palette:{primaryColor, ...}}}`). When
PC2 toggles the desktop theme, ENM follows on the next render.

The drawer's *Appearance* section still lets the operator override
("Switch to dark mode" sets `enm-theme-mode = 'manual'`) and revert
("Follow ElastOS theme" resets it to `'auto'`). Manual override
wins until the operator explicitly switches back.

## What didn't change

- **Backend** — every `enm-server` route added in Wave 6 (`/update`,
  `/bpos/activate`, plus the existing `/compact-logs`) sits alongside
  the v0.3 endpoints. The SQLite schema is identical to v0.3 — no
  migrations.
- **Healing engine** — F1 still on by default; F2-F19 still opt-in.
  The drawer's *Try to fix problems without asking me* toggle reads
  to the same enable list as the technical view's per-rule controls.
- **Install flow on disk** — same `/data/enm/` layout. The setup
  conversation is just a friendlier shell over the v0.3 setup
  endpoints.
- **Architectural invariants** — all 7 from
  [architecture.md](architecture.md) still hold. v0.4 doesn't
  introduce new invariants; it just changes how the existing ones
  surface to the operator.
